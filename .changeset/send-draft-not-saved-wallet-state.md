Keep the send form out of `localStorage`, and clear it when the account or network changes (#197). `createAppStore()` saves only the display preferences `isBalanceHidden` and `balanceDetailExpanded`, still under `redux_localstorage_simple_ui` and still through redux-localstorage-simple, as a JSON object of those two fields, a second after an action that changed one of them; an action that changes neither writes nothing, so a page no longer puts its older preferences back over a change another page saved unless it changes one itself. The store loads only those two from the saved value, so the rest of the `ui` state starts at its initial values. As the store is made, a saved value that holds anything else, such as the whole `ui` state with the send form that earlier builds saved, or no JSON object at all, is replaced at once with the two preferences alone, or removed when it cannot be replaced, and a preference that is not a boolean of the saved object's own takes its initial value; a value that holds just the two is left as it is, and a missing one stays missing. The send form (`uiTxCreateScreen`), the fee bar (`feeRateBar`), `addressInput` and `amountInput` stay in the store while the page is open, and take their initial values in the same store update in which the selected account (`accounts.current.address`) or network (`settings.chainType`) changes from one known to another; nothing is cleared while the store has no account (an empty address), nor when the same account and network come back, as after a lock and an unlock or a read of the same account. The `ui` state's new `sendFormScope` records the account and network the form's values were entered under. `useTxCreateScreenLogic` returns `formKey`, a new key for each scope the store records (the first account and network known, which clears nothing, and each clear for another account or network, also for one that comes back), for an input that keeps its own copy of a value to be keyed on, and reads the saved replace-by-fee choice again when the key changes, as a newly opened form does; a read sets the form's choice only if no later read has started and the user has not changed the choice since it started. A send that `onClickNext` prepares is dropped when, before it is built or refused, Next is clicked again, the screen is left, or the store clears the form for another account or network: it opens no confirm screen and sets no error, so only the latest Next of a mounted form does either.
