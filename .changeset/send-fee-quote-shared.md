Read the send screen's fee quote once and use it for both the fee bar and the abnormal-fee check, so the rates the fee bar offers and the rate the warning compares against can no longer come from two different quotes. `useTxCreateScreenLogic` returns the quote it reads as `feeQuote`, and `useFeeRateBarLogic` takes it as an optional `quote`: given one, the fee bar reads no quote of its own and offers that quote's rates in the same render in which the screen checks the fee against it. Without one, the fee bar reads its own quote as before. The new `useFeeQuoteRead` reads the quote, again after a network change, and names each read in `FeeQuoteState`'s `read`; a name is never reused, also across pages, since the fee-bar store is saved. With each rate it chooses for a tier, the fee bar records in the store which read and option it chose it from (`feeRateSource`, null for a Custom rate), and the new `feeRateOrigin` compares that record with a quote. Until the selected tier's rate comes from the screen's current quote, and the screen has checked that rate, the send screen keeps Next disabled, judges nothing, and shows the estimated fee and the total as `--` (`feeEstimatePending`) rather than values at another rate. That holds while the quote loads, also after a network change, while a low-fee read for it is pending, after a quote without qbit metadata or a failed read lands, and after another tier is selected. A send without a preview is held the same way, with Next disabled, but it shows no fee or total. Until then the rate is the fee bar's default of 1 sat/vB, or a rate from an earlier quote, possibly another network's. While held, the send screen also shows no error from its checks of the fee, which ran at a rate not yet settled; the checks of the address, the amount and the memo still show. A tier the quote does not list gets a fallback rate with no source, so a fallback is never taken for the quote's rate. The consolidation screen now reads its quote with `useFeeQuoteRead`, returns it as `feeQuote` for its fee bar, and prepares no batch until the bar's rate for a selected tier comes from it; it offers no batch priced at a rate other than the selected one. Both screens decide with the new `useFeeRateSettled`. A Custom rate is judged, and can be sent or consolidated at, while the quote loads. A fee-bar store saved without `feeRateSource` reads as having none. Low-fee mode now puts its slow rate into a new list instead of changing the quote's own.

While a quote loads, the fee bar keeps the options and the rate it already had instead of falling to a default rate of 1 sat/vB. When the fee quote cannot be read, the bar sets `feeEstimateUnavailable`, uses the relay floor as the rate, shows that rate in the custom-rate input instead of a tier's earlier rate, starts a Custom rate from it, and offers only the Custom option, so the user can still set a higher rate; a Custom rate set there is kept, and while it is below the relay floor Next stays disabled. Each option in `feeOptions` now carries the option `index` it selects, so the Custom option selects Custom wherever it stands, and at most three tiers are offered. `fallbackFeeRate` is the relay floor only while the floor is the rate in use, so the bar's notice names the floor only then; it is undefined for a Custom rate, a tier above the floor and a read-only bar. A read-only bar never changes the selected rate, which the send screen shares with it. A failed low-fee read falls back to the quote's own rates, and no failed read leaves an unhandled rejection. `supportLowFeeMode` is now true only when a low-fee read for the current quote succeeded and its slow rate below 1 sat/vB replaced the quote's own, so a Custom rate below 1 sat/vB is not accepted before a quote arrives, while its low-fee read is pending, or after that read failed.
