Read the send screen's fee quote once and use it for both the fee bar and the abnormal-fee check, so the rates the fee bar offers and the rate the warning compares against can no longer come from two different quotes. `useTxCreateScreenLogic` returns the quote it reads as `feeQuote`, and `useFeeRateBarLogic` takes it as an optional `quote`: given one, the fee bar reads no quote of its own and offers that quote's rates in the same render in which the screen checks the fee against it. Without one, the fee bar reads its own quote as before. Until the selected rate has caught up with a newer quote, the send screen shows the total without judging the fee against that quote. Low-fee mode now puts its slow rate into a new list instead of changing the quote's own.

While a quote loads, the fee bar keeps the options and the rate it already had instead of falling to a default rate of 1 sat/vB. When the fee quote cannot be read, the bar sets `feeEstimateUnavailable`, uses the relay floor as the rate and offers only the Custom option (none in a read-only bar), so the user can still set a higher rate; a Custom rate set there is kept and is never below the relay floor. The Custom option selects the Custom index wherever it stands in `feeOptions`. A failed low-fee read falls back to the quote's own rates, and no failed read leaves an unhandled rejection. `supportLowFeeMode` is now true only when a low-fee read for the current quote succeeded and its slow rate below 1 sat/vB is offered, so a Custom rate below 1 sat/vB is not accepted before a quote arrives, while its low-fee read is pending, or after that read failed.
