A recovery migration review signs every plan in one press when nothing outside the migration signs in between (#156). Before, each plan's budget was prepared before any of them signed, so once the first plan of a source signed, every later plan from that source was refused with "P2MR signature budget changed after approval", and the user pressed again for each one. `prepareQbitRecoveryMigration` now opens one signature batch for each source key with two or more of the plans it returns, and marks each plan with `qbitSignatureBatch`; plans from different keys stay in separate batches. Each plan's restored-floor challenge is still confirmed on its own, and a signature made outside the batch between plans is still refused. Preparing the same review again reopens the same batch; budgets prepared again after a plan signed get a batch of their own, and a batch being signed is left open. A preparation that cannot open every batch closes those it opened, and leaves open those it only reopened, which another review may be signing from. `signPsbtV2` refuses a plan whose batch is no longer open, because its review ended or was replaced or the wallet locked, with `ErrorCodes.QBIT_RECOVERY_REVIEW_INTERRUPTED`, before any of it is signed. A failed website request now releases only the restored-floor challenges its approval step prepared, which the request records, never ids in the page's own parameters, so a refused request cannot release another review's challenge or close a migration's batch with it.
