Keep the selected account when Receive opens (#139). `ensureQbitReceiveIntent` showed the wallet's latest receive intent and switched the selected account to the account that owns it, or, when that address had activity, issued the next address and switched to it. It now shows the selected account's own address and never changes the selection or issues another address. A used address stays current and is marked used. An exhausted address, a never-issued one past the restore gap, or an unused one that a recovery migration plan pays is not offered. Receive offers New Address instead while an index is left within the restore gap; when issued addresses and migration reservations fill it, for example with 20 or more pending sweeps, it shows that no safe address is available until activity lands. An address reserved for a migration is also left out of the previous addresses. An unused address on screen becomes the ledger's current intent, which records it as issued the first time.

Only `createQbitReceiveIntent` (New Address) switches accounts. It never issues an index that a recovery migration plan pays, even one the receive ledger has not recorded, such as after the destination wallet is removed and its seed imported again, or the anchor a version-1 plan pays; when no other index is left within the restore gap, it rejects as it does at the gap limit. It saves the selection before it returns, since nothing re-selects the latest intent any more, and it rejects when the recheck finds activity on the address it just issued, instead of returning the unchanged state. `ensureQbitReceiveIntent`, `createQbitReceiveIntent` and `getQbitReceiveState` reject when another account or wallet is selected while they run, and New Address then does not switch accounts.
