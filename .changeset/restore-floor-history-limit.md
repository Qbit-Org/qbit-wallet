Let a restored wallet lift its signing gate when an address's history is too long to enumerate (#264). `observeQbitPqcSignatureActivity` used to throw for an address with more than 6,400 transactions, so the restore floor scan never completed and `PQC_FLOORS_PENDING` locked every signature for good. It now reads such an address's floor from its statistics, `chain_stats.spent_txo_count + mempool_stats.spent_txo_count`. That is the count the full history read must match before it accepts a floor. The statistics read applies only when the statistics themselves show a history the scan does not enumerate: past the transaction cap or, on an Esplora surface, more pending transactions than its mempool listing returns (50; mempool-qbit pages them). It continues the tip-and-statistics bracket the cap check opened, so a block that lands meanwhile holds the retry for the tip-advance settle floor, and it retries per address like the full read. A walk that hits the client's page or transaction ceiling (`pagination_limit`) while the statistics say the history fits still fails, because the two disagree. The default page budget now follows the transaction cap (257 pages for 6,400), enough for an Esplora walk to reach it. It fails closed on invalid statistics, on statistics that list more transactions than outputs they fund or spend, and on statistics that spend more outputs or value than the address was paid. Every other failure still fails the observation. Any unstable floor observation during which the chain tip advanced, or after which the tip cannot be read, now waits out the tip-advance settle floor before its retry, whatever the instability was: moved statistics, a count mismatch, or a shifted history page. `observeQbitPqcSpentOutpoints` still requires the full history.

`@qbit/wallet-shared` adds `QbitRestoreFloorSource` (`'history' | 'address-stats'`) and `QbitRestoreFloorSourceRecord` (index, pubkey, source). The result now says which read set the floor (`QbitPqcSignatureActivity.floorSource`). `@qbit/keyring-service` passes an observer's `floorSource` through as `QbitPqcRestoreFloorScan.floorSources`, and `QbitRestoreFloorScanSummary.floorSources` carries them to the restore report. The restore report names the accounts read from statistics. No vault field changes.
