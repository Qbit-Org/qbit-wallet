Show the balance total while the wallet has not finished reading an account's outputs and no balance is shown yet, keep a balance already shown when a refresh cannot read every output, and poll the balance politely (#36, #124).

- `setBalanceV2` stores `utxoReadIncomplete`, and `useBalanceCardLogic` returns `utxoReadIncomplete`, `utxoReadIncompleteText` (`balance_outputs_incomplete`) and `utxoReadIncompleteDetailText` (`balance_outputs_incomplete_detail`): where no split is shown for the account on that network, the card shows the total with a note, Available and Unavailable as `--`, and the load error only when the read itself failed. Where a split is already shown, `setBalanceV2` records such an answer as a failed refresh instead, under the same request ordering: the last split stays, the card shows `balance_refresh_error` with Try again, as it did before, and nothing of the answer is stored. A split from an older read that arrives after such an answer takes its place the same way: the card shows that split with `balance_refresh_error` and Try again.
- The card's poll never runs a tick beside one of its reads that is still in flight, unless that read has been in flight for 60 seconds (one that falls due meanwhile runs 2 seconds after the reads settle, so the several reads an account with thousands of outputs needs follow each other closely), pauses while the page is hidden and reads when it is shown again once a read is due, and waits 10, 20, 40 seconds and so on, at most 2 minutes, after each failed read ends (a rejection, an answer whose read of the outputs got no further, `utxoReadFailed`, or a read given up on after 60 seconds, counted from the give-up) until one succeeds. An answer that ran out of time part of the way through the outputs keeps the normal pace; one that kept nothing new carries `utxoReadFailed` and backs off. Try again still reads at once. A change of account or network starts a new cadence.
- `useFetchBalanceCallback` resolves with the balance it read (undefined without an account).
- `useFetchBalanceCallback` no longer calls `getAddressSummary` before the balance: nothing read its answer, and its failure failed the balance. `getAddressSummary` is removed from the `WalletController` proxy type.
- The send screen's loading overlay lasts at most 1.5 seconds (`SEND_OUTPUTS_OVERLAY_MAX_MS`) while the screen's first read of the account's outputs runs. A read still running then goes on behind the form, which can be filled in meanwhile: Next stays disabled, MAX fills nothing, and `useTxCreateScreenLogic` returns `outputsLoading` with `outputsLoadingText` (`send_outputs_loading`) for a note that says why. A read that fails returns `outputsLoadFailed` with `outputsLoadFailedText` (`send_outputs_load_failed`) in place of a silently disabled Next. Outputs the page cached on an earlier visit serve the form only once a read of this visit has landed for the account and network, as they did behind the overlay; when this visit's first read fails they no longer serve.
- `useFetchUtxosCallback` asks the background to ride out the explorer's server errors (`getQbitUtxoSnapshot(readId, true)`) only for a read its caller gave a signal, as the send screen's own reads, the one it opens with and each one it makes again while open; every other read passes its read id alone and fails on such an error as fast as 1.0.9's did. `WalletContext.getQbitUtxoSnapshot` takes the optional `rideOut: true`.
