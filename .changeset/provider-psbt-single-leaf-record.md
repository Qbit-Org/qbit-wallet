Refuse a website PSBT that lists the account's P2MR leaf ambiguously before any signature is spent (#13). An input could list the account's leaf twice, for example first with a control block that does not commit to the spent output and then with one that does. The signing plan and the finalize dry run passed, because finalize skips a control block that does not commit, so the approval signed and spent a signature, and the provider's check of the signed PSBT then compared the witness with the first record and failed with `signed PSBT changed the approved P2MR leaf`. `prepareQbitProviderPsbt` now rejects with `-32602`, before the approval and the signature-budget preflight, an input that lists the account's leaf more than once, whether or not every record commits, or whose one record has a control block that does not commit to the witness UTXO program, as does an input the account signs whose witness UTXO is not a P2MR output or whose P2MR merkle root differs from it. Except for a leaf listed more than once, such inputs were already refused, but with a protocol error. The provider checks the signed PSBT against that one record, the one finalize reveals, by the same rule, and reports a failure there as an internal error, since the signature is already spent. Leaf records for other leaves are not checked.
