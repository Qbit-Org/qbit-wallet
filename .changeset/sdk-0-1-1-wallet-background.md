'@qbit/wallet-background': patch

Use `@qbit-oss/api`, `@qbit-oss/protocol` and `@qbit-oss/pqc` 0.1.1. A broadcast whose 429 reply could not be read in full, or relays the explorer's lost connection to its node, now ends as an unknown outcome instead of being sent again by the client and reported as rate limited, and a 429 saying the node already has the transaction counts as sent. A reply that stalls ends as an unknown outcome whatever its status. The explorer clients' new `maxResponseBytes` is the wallet's own 64 MiB reply limit, which holds a full history page of the largest standard spends, and the wallet's explorer fetch now enforces the same value: a reply past it fails as `response_too_large` (it was a `parse` error) and is not retried, and a broadcast reply past it stays an unknown outcome that is not sent again. A website PSBT that qbit Core would refuse is refused before its approval window opens: one with no outputs, two inputs spending one output or an input spending the null outpoint gets an error naming the rule, and one with a key that has data after a type that must stand alone gets "invalid psbt".
