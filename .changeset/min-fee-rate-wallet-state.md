Take fee rates from qbit Core's relay floor of 0.25 bits/vB on the send and consolidation screens (#182). `useFeeRateBarLogic` returns `minFeeRate`, the lowest rate the Custom input offers, which is `QBIT_MIN_RELAY_FEE_RATE` in every state; `supportLowFeeMode` is still returned but no longer decides it. `adjustFeeRateInput` keeps a rate as typed: it no longer raises a Custom rate below 1 bit/vB to 1 (or one below 0.1 to 0.1 in low-fee mode), nor replaces a zero with the default rate, so a rate still being typed, such as "0." or "0.2", stays in the input while Next stays disabled, and the screens refuse a rate below 0.25 as they refuse one above the ceiling. For a Custom rate typed below 0.25, `useTxCreateScreenLogic` and `useQbitConsolidationScreenLogic` also say why in their `error`, with the new `fee_rate_below_minimum` message naming the floor, by one decision both screens share (`feeRateBelowMinimumError` beside `feeRateOrigin`): the typed text decides, so a zero that is no longer being typed ("0.0", "0.00", "00") gets the message as "0.1" and "0.24" do, while an empty input, "0" and "0." (still being typed) and a tier's rate get none; the consolidation screen gives it only while it has a batch to prepare, and prepares none while it shows it. Text that is not plain decimal digits, such as a pasted "0,25", "1e3" or "-1", clears the input instead of being read as another rate. Tiers below 1 bit/vB are selected at their own rates, and typing the selected tier's rate keeps the tier. Without estimates the rate in use is `QBIT_FALLBACK_FEE_RATE` (1 bit/vB), not the floor: after a failed read the bar writes it to the store, shows it in the input and starts a Custom rate from it, `fallbackFeeRate` is that rate, and a tier of a quote without estimates is recognised by it; a Custom rate down to 0.25 is still accepted there. The fee-bar store's initial rate and the placeholder review's `recommendedFeeRate` now name `QBIT_FALLBACK_FEE_RATE`, still 1. Low-fee mode's fixed slow rate is the relay floor instead of 0.1 bits/vB. The `above_relay_floor` warning gives its multiple of the 0.25 bits/vB floor, so 100 bits/vB reads as 400× the network minimum. The new `formatFeeRate` export shows a fee rate as the screens and the fee warnings show it: rounded down to hundredths, so a rate shown is never higher than the rate paid (936 bits for 3,817 vB, 0.2452 bits/vB, shows as 0.24, not as 0.25), a rate already in hundredths as it is, a positive rate below 0.01 as "<0.01" and one that is no finite number of 0 or more as "-"; the fee warnings use it in place of rounding to the nearest hundredth.
