Let a consolidation batch's size be chosen, and name the explorer's refusal of a transaction as too large (#170). `QbitConsolidationRequest` (`feeRate`, `enableRBF`, `maxInputs`) is what `createQbitConsolidationPsbt` takes, and `QBIT_CONSOLIDATION_MIN_INPUTS`, `isQbitConsolidationBatchSize` and `assertQbitConsolidationBatchSize` (a `RangeError` naming the range) check a size, a whole number from 2 to the account's `maxInputCount`, in the background and on the screen alike. That maximum stays qbit Core's standard size: `qbitP2mrMaxStandardInputCount` allows 106 single-key inputs for one or two outputs, and the wallet relies on the explorer measuring the same size, as it does from explorer 1.1.0 (qbit-explorer#58). Breaking changes: `QbitConsolidationBatch.maxInputs` and `QbitConsolidationStatus.batchShape` (`QbitConsolidationBatchShape`, the shape a batch of any size is priced with) are required, and `QbitBroadcastFailureReason` gains `too_large`: the explorer refused the bytes as over its size limit, with code -3 and before any node saw them. Deployments before explorer 1.1.0 weighed base bytes ×4 plus witness bytes and so refused single-key P2MR transactions of 103 to 106 inputs.
