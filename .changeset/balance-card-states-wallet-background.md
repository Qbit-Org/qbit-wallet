Tell the wallet page how a balance read goes, and keep the last complete balance for a page opened later. `getAddressBalanceV2` takes an optional `progressId` (`QbitAddressBalanceOptions`): the page whose call it is then gets the total as soon as the address statistics answer, and how many of the listed outputs have been read, at most four times a second, only when the count moved, and never fewer than before for the same listing. An output read from the listing alone or served from facts kept from an earlier read counts as read. Nothing is sent once the address is no longer the selected account's, the network changed, the wallet reads locked or the read's kept facts were cleared, and the timer stops however the read ends. The read makes no request for this and answers as before.

The controller keeps the last complete answer of `getAddressBalanceV2` (its split known, or past the explorer's listing limit) per network and address, in memory only, for the eight addresses most recently read or served per network, with when its read began. The new UI method `getKeptAddressBalance` serves it to a newly opened page, which shows it dimmed while its own first read runs; it reads nothing from the explorer and answers `null` while the wallet reads locked. The kept answers are forgotten wherever the reused balance answers are (a lock, a reset, a keyring removal, a network or endpoint change, dropped regtest clients), and both as a transaction is submitted and as its submission settles; a read that began before then keeps nothing, though the reads in flight still tell their pages how they go. `getQbitSpendableBalanceV2` takes an optional `observer` (`QbitBalanceReadObserver`) told the total and how far the outputs are classified; it changes nothing in the read.
