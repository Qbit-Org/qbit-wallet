`getAllDisplayedKeyrings` no longer keeps a list of the wallets that a change to the keyrings overtook. A read that started before a change (an account added or removed, a wallet added or removed, an address type, HD path, recovery, receive or signature-counter change, a lock, an unlock or a reset) and settled after it kept the wallets as they were before the change, although the change had cleared the list, and every later read returned them until the next change: an account just derived was missing, a removed wallet was still listed, and wallets were listed while locked. The forced read, `getAllDisplayedKeyrings(true)`, kept such a list too. A read now keeps its list only when no change landed while it read and no read that started after it has kept its own; an overtaken read still returns the wallets as it read them, and keeps nothing, so the next read reads them again. Every Qbit HD wallet in a list now shows its recovery state for the network the list is kept under, which the read takes when it starts: a network switch while the list was read could show some wallets for the new network in the list kept for the earlier one. `displayForKeyring` takes that network as an optional fourth argument, `{ network }`, and otherwise reads the active network as before. A signature-counter write that fails, and a counter reservation's rollback, now clear the list as well, since the live counters changed either way. `removeKeyring` takes an optional second argument, `{ beforeRemove }`: a check it runs right before it empties the wallet's slot, under the exclusion that every wallet addition and removal and every account or address type change takes, so that what the check reads still holds when the wallet goes. When the check throws, nothing is removed and its error is passed on; a lock while it runs refuses the removal as well.
