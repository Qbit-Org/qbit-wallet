Show each account's total in the account switcher.

- The page-side `WalletController` type declares `getQbitAccountTotals(addresses)`, the totals the background keeps, which reads nothing from the explorer, and `readQbitAccountTotal(address)`, which answers from the kept total while it is fresh and reads it otherwise.
- `useAccountSwitcherTotals(keyrings)` returns `{ hidden, totals }`: each listed account's total (`totalBalance`, in sats or `null`), whether it is `stale` (the latest read did not measure it, or the read says it may be from before a transaction the wallet submitted) and whether it is still `pending`. While the switcher is open on a network it asks about each account of the wallets that are not corrupted once: first all together for the kept totals, the current wallet's accounts first (at most 1,024 addresses per request), then one read each for those without a fresh kept total for that network. The reads go in that order, at most 4 out at a time (`ACCOUNT_TOTAL_READS_AT_ONCE`, as many as the background reads from one explorer at a time), the next one sent as one settles; those still waiting when the switcher closes, or the page changes network, are not sent, and those waiting while balances are hidden are asked about again once they show. Accounts the list gains while it is open are asked about the same way, and all of them again when the page comes back to a network after another; nothing is polled or retried, and nothing at all is asked while balances are hidden (`isBalanceHidden`), also once they are hidden while the kept totals are out. A refused `getQbitAccountTotals`, as from an older background, leaves every account to its read, and a rejected read counts as a failed one.
- An answer is used only for the address asked about and for one of the wallet's networks (`ChainType`). A read's total that the background does not call fresh may be from before a transaction the wallet submitted: it is stored and shown as stale, as one whose read failed is; a kept total that is not fresh is read again, as before, and does not clear the stale mark of a total stored stale before it: that total stays stale until a read's answer, or a fresh kept total, says otherwise. An answer for another network is stored for that network and counts as a failed read on the page's: a total shown before stays, marked stale. A kept answer without a total stores nothing, so a total shown before does not turn stale when the background has kept none, as after it restarted.
- The answers go to `accounts.accountTotalsMap`, by network and then by address, in maps without a prototype, so any address is a key like any other (`storeAccountTotals`). Answers that arrive within 50 ms of each other (`ACCOUNT_TOTAL_ANSWER_BATCH_MS`) are stored in one update, and those still waiting when the switcher closes are stored then. An answer replaces nothing the answer of a newer request stored, and one without a total keeps the total stored before it, marked stale. Only the current network's totals are returned. The map is kept for the page's lifetime, so the switcher opened again shows at once what it showed before, and it is never saved: `createAppStore` still saves only the two display preferences.
- `resetWalletState` and `accountActions.reset` clear the totals and drop the answers of the requests made before them (`accountTotalsAsked`, `accounts.accountTotalsFloor`), so a total read for an erased wallet never comes back. With no switcher request made, they still leave the accounts slice at its initial state.
- `useCurrentAccountBalanceTotal()` returns the current account's total once the home screen's balance card has one read on the current network (`{ address, totalBalance, stale }`), else `null`, so the switcher's row for that account shows the card's figure.
- `isSatoshiAmount(value)`, whether a value is a number of sats (a safe integer, 0 or more), is exported, so the extension checks a total as the store does.
