Let the consolidation screen choose how many outputs each batch merges (#170). `useQbitConsolidationScreenLogic` holds the batch size as typed (`batchSizeText`, `onBatchSizeChange`, `onClickBatchSizeMax`) and opens at the account's maximum, `QbitConsolidationStatus.maxInputCount`, 106 single-key inputs. It accepts only digits naming a whole number from 2 to that maximum, checked with `isQbitConsolidationBatchSize`, the rule the background applies to the request; anything else disables Prepare and sets `batchSizeError`. The size goes with the request as `maxInputs`, the maximum included, and it is part of what a batch was prepared for: a batch prepared at another size is dropped, and a prepare still running for one is never published. Until the status loads there is no maximum to check a size against, so no size is offered. A batch prepared after a failed status read carries the size the route names when it could be one (a whole number of at least 2), which the background checks against its maximum and refuses with a readable error when it is past it, or none, and the background uses its maximum; once the status loads, a batch prepared at that size stays. A route's size can be past the maximum when the maximum is lower for the account or version the screen opens on than for the batch the size came from. While the maximum is unknown, a prepare that fails reads the status again, as one that succeeds always does, so a status that loads then gives the screen its maximum, and a route's size past it gives way to the maximum; once the maximum is known, a failed prepare reads no status. The size, its range, the fee preview and the cost note are offered only for an account over the limit. `feePreview` gives the fee and size of a full batch of the chosen size at a settled rate (`estimateQbitP2mrTransaction` on `QbitConsolidationStatus.batchShape`), and `costNote` how much more in fees smaller batches take than the largest, in whole percent; both stay empty without a batch shape. A failed status read or prepare now shows its message: the wallet proxy rejects with a plain `{ message, stack }` object, which the screen showed as "[object Object]".

The next batch keeps the size. `useTxConfirmScreenLogic` passes the batch's `QbitConsolidationBatch.maxInputs` to the success screen as `consolidationMaxInputs`, and Consolidate next batch opens `QbitConsolidationScreen` with it as `maxInputs`. The screen checks that value against the current maximum and opens at the maximum when it is missing or out of range. Back from the confirm screen keeps the size chosen too: before it opens the confirm screen, the consolidation screen writes the batch's size with the account's network and address into its own route state, and it opens at the maximum for another account or network. A size the user types likewise applies only to the account and network it was typed for: the screen holds one typed size, not one per account, so another account or network opens at its own opening size, and once a size is typed there, switching back opens the first at its opening size. A batch that reaches the success screen through the failure screen's Retry or Check status still offers the next batch at its size: `useTxConfirmScreenLogic` passes `consolidation` and `consolidationMaxInputs` to `TxFailScreen` as well, and `useTxFailScreenLogic` hands them on. The confirm, failure and success screens check them the same way: only `consolidation: true` marks a batch, and only a safe integer is passed on as its size. `RouteParamList.QbitConsolidationScreen` takes the optional `maxInputs`, `chain` and `address`, `RouteParamList.TxFailScreen` the optional `consolidation` and `consolidationMaxInputs`, a route whose params are all optional can now be opened without any, and `WalletController.createQbitConsolidationPsbt` takes a `QbitConsolidationRequest`.

After the explorer refused a transaction as too large to broadcast (`too_large`), `useTxFailScreenLogic` offers no Retry (`canRetry` is false) whatever the outcome, since the explorer refuses the same bytes the same way; Check status stays for an unknown outcome.
