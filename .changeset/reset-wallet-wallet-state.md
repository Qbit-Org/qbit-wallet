Add the page side of Reset Wallet and the Settings → Security screen. The page-side `WalletController` type declares `resetWallet(password, options?)`; breaking change: it no longer declares `resetAllData`, which the wallet's pages could never call. `useResetWallet()` returns a callback that asks the background for the reset. `resetWalletState` is an action every slice handles: one dispatch returns the store to its first-run state (`isBooted` and `isUnlocked` false, no accounts, wallets, transactions or drafts), keeping `locale`, `themeMode` and `isReady`, so the persisted `ui` slice is saved empty. `RouteParamList` gains `SecurityScreen`, and `useSettingsTabScreenLogic` returns a `settings_security` row, placed before `settings_appearance`, that opens it. `useCreatePasswordScreenLogic` shows a `boot` rejection's message (or `unknown_error`) in its toast; it passed the rejection object itself before, which arrives from the background as a plain object and broke the screen. The page-side `WalletController` type declares `getWalletId()`, and the declarations of `unlock`, `changePassword` and `boot` name the reset errors they can reject with.
