Report the phishing network layer as a whole, and leave the source tab alone for a link that opens a new tab where the warning redirect rule already shows the warning.

`GET_PHISHING_STATS` now also answers `protection` when DNR is available: `degraded` while the block rule is not installed, or while a redirect rule that cannot fire for lack of host access may still be in place because its removal is pending or failing; `unknown` while either rule cannot be read, or the redirect rule's state does not arrive within two seconds; and `full` otherwise. It lists the reasons, including `site-access-withheld` when the block rule is not installed and the browser's permission check reports site access withheld (`site-access-unknown` when it cannot say), and the warning redirect rule's own state (`installed`, `not-wanted`, `missing`, `removing`, `removal-failed` or `unknown`) with its host access, last error and next retry, as the read found them. Before, the health covered only the block rule and reported `installed` while such a redirect rule was still in place. The read takes that rule and host access from the browser as they stand, without waiting for an update to the rule, and no update waits for it, so a read the browser holds up delays no removal. Concurrent reads share one until a request gives up on it. A read that finds that rule with no attempt scheduled or queued starts its removal once its answer reaches a request still waiting for it, without clearing a recorded failure or superseding a queued retry. `networkRules` and the stats come back whatever happens to the redirect rule's read, and an MV2 answer has no `protection`.

`CHECK_NAVIGATION` takes an optional `newTab` flag, which the content script sets for a `_blank` link and for a Ctrl-, Cmd- or Shift-click. When it confirms within a second that the redirect rule is in place with host access for the link's canonical host, with no update to the rule queued or running, the background leaves the sending tab and its page alone and answers `leftToRedirectRule: true`; otherwise, including on a timeout or a failed check, it sends that tab to the warning page as before.

In `@qbit/wallet-shared`, the types `PhishingProtectionHealth`, `PhishingProtectionStatus`, `PhishingProtectionReason`, `PhishingWarningRedirectHealth`, `PhishingWarningRedirectHostAccess`, `PhishingWarningRedirectStatus` and `PhishingStatsResponse` are new, as is `PHISHING_PROCEED_REFUSED_ERROR`, the error `SKIP_PHISHING_PROTECTION` answers for a hostname it does not lift.

The extension's warning screen offers Proceed only for a hostname that passes `parseDnrDomain`, the check the background applies to Proceed; for any other, and when the background refuses a Proceed it offered, it says that the site cannot be opened from there, rather than failing with an unknown error.
