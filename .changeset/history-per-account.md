Show only the selected account's transactions in History (#77). `getAddressHistory` read every account of the wallet as one history, so each account listed the others' transactions and a payment between two accounts showed as a transfer to itself in both. It now reads only the selected account's own address, the address its balance reads: the first page, later pages, the snapshot a refresh reuses and the revision probe all cover that one address. A payment between two accounts is a send in the paying account and a receive in the other, with the other account's address as the counterparty. With one address the refresh always uses the revision probe, so history no longer calls `probeQbitAccountHistoryAncestry`. The history key (`scopeKey`, and `useHistoryScopeKey` in `@qbit/wallet-state`) is now `qbit-account:<chain>:<account pubkey>`, one per account, so a snapshot of one account is refused for another and a read that finishes after an account switch is stored under the account it read. `getAddressHistory` and `getAddressCacheHistory` refuse an address that is not the selected account's before reading the explorer, and a refresh whose account changes during its revision probe ends there, whether or not the probe succeeded, instead of scanning the account again. History cached by earlier builds under the wallet-wide `qbit:<chain>:<first account's pubkey>` key is never read, and `@qbit/preference-service` drops those entries when it loads. Because the cache now holds one entry per account, `updateAddressHistory` keeps only the 16 most recently written entries. Receive selects each new receive address as it moves on, so History then shows that address's transactions, as the balance card does.
